# חנות התוספים של אוצריא

קובץ הרצה אחד לווינדוס. הוא מסנכרן את קטלוג התוספים מ-otzaria.org אל
תיקייה שצמודה לו, מזהה איזו גרסה של אוצריא מותקנת במחשב, ומתקין את התוסף
שתואם לה.

```
חנות התוספים.exe      ← זה כל מה שמפיצים (‎0.6MB)
Data\                  ← נוצרת לידו בהרצה הראשונה
  catalog.json           הקטלוג הממוראה
  plugins\<id>\...       קובצי ה-.otzplugin, האייקונים וצילומי המסך
  state.json             מה זוהה על ההתקנה של אוצריא במחשב הזה
  logs\store-<תאריך>.log
```

## עובדת בלי אינטרנט

מרגע שהסנכרון הסתיים הכול יושב ב-`Data\`, וההתקנה אינה נוגעת ברשת. אפשר
להעתיק את התיקייה לכונן נייד ולהתקין ממנה במחשב מנותק.

## החבילה המלאה

למי שאין רשת גם בפעם הראשונה מתפרסמת, לצד ה-exe הרזה, חבילה מלאה: אותו
קובץ הרצה בדיוק, עם מראה שלמה של כל התוספים משורשרת לסופו.

```
Otzaria-Plugin-Store-Full.exe   ~96MB, הרצה אחת
        ↓
חנות התוספים.exe                עותק של עצמו בלי המטען
Data\                            כל התוספים, מוכנים
```

ההרצה הראשונה פורסת את `Data\`, כותבת עותק רזה של עצמה, מפעילה אותו
ויוצאת. הרזה שואל אם למחוק את קובץ ההתקנה ואינו מוחק מעצמו — אותה חבילה
עשויה להיות מיועדת גם למחשב שני.

* **החילוץ מחליף** את `plugins\` ואת `catalog.json` במלואם, ואינו ממזג.
  `state.json` ו-`logs\`, שהם מקומיים למכונה, אינם נוגעים.
* **החותמת נכתבת אחרונה.** חילוץ שנקטע משאיר תיקייה בלי חותמת, וההרצה
  הבאה עושה אותו שוב — המטען עדיין בתוך ה-exe.

הפורמט מוגדר ב-`native/tools/pack_overlay.mjs` ונקרא ב-`native/src/overlay.cpp`.

## איך זה קובץ אחד

| | |
|---|---|
| ה-loader של WebView2 | מקושר **סטטית** → אין `WebView2Loader.dll` |
| ה-CRT של Visual C++ | מקושר סטטית (`/MT`) → אין `vcruntime140.dll` |
| קובצי הממשק | דחוסים (LZMS) כ-resource בתוך ה-exe → אין תיקיית ממשק |

מנוע התצוגה הוא ה-WebView2 Runtime שכבר נמצא במחשב — מותקן מראש בווינדוס
11, ומגיע עם Edge בווינדוס 10 — ולכן אינו נספר בגודל.

## מבנה

```
native/
  src/            ה-host ב-C++: חלון, WebView2, וגשר לקבצים/רשת/רג'יסטרי
  web/            הממשק וכל הלוגיקה — HTML/CSS/JS, בלי bundler ובלי npm
  test/           בדיקות `node --test`
  tools/          כלי בנייה ופיתוח, וכלי האריזה של החבילה המלאה
  third_party/    ה-SDK של WebView2 (מובא מ-nuget, אינו בגיט)
  build.ps1       הבנייה כולה
  VERSION         מספר הגרסה — מקום אחד
tool/
  set_version.sh      מציב את הגרסה (מריץ אותו ה-CI)
  make_app_icon.ps1   בונה את ה-ico ואת האייקון שבשורת הכותרת ממקור אחד
```

### חלוקת העבודה בין ה-host ל-JS

ה-host הוא **מעטפת טיפשה**: הוא נותן חלון, ומגיש קבצים, רשת, רג'יסטרי
ודיאלוג שמירה. כל הלוגיקה — המודלים, בחירת הבילד התואם, הסנכרון, פירוק
הכותרות, קריאת ה-manifest — יושבת ב-`native/web/js/`.

כך הלוגיקה נבדקת ב-`node --test` בלי חלון ובלי ווינדוס, ומה שנשאר ב-C++
הוא קריאות מערכת שאין בהן החלטות.

לכן גם **אין פרסר JSON ב-C++**: `JS → host` הוא שדות מופרדים ב-U+001F —
תו שאינו חוקי בנתיב ואינו מופיע בכתובת — ו-`host → JS` הוא מחרוזת JSON
שנבנית עם escaping בלבד.

## בנייה

דורש Visual Studio (או Build Tools) עם כלי C++. אין תלות ב-CMake, ואין
צורך להתקין SDK של שפה כלשהי.

```powershell
.\native\build.ps1            # בנייה
.\native\build.ps1 -Run       # בנייה והרצה
.\native\build.ps1 -Clean     # מאפס את native\build\
.\native\build.ps1 -Debug     # עם סמלי ניפוי, בלי אופטימיזציה
```

הסקריפט מביא בעצמו את ה-SDK של WebView2 מ-nuget, אורז את קובצי הממשק,
וצורב את משאב הגרסה.

## בדיקות

```bash
cd native && node --test
```

בלי שום תלות npm. הבדיקות מכסות את הלוגיקה הטהורה: השוואת גרסאות, בחירת
הבילד התואם, פירוק כותרות ההורדה, המודלים, התאריך העברי, קורא ה-ZIP,
בטיחות הנתיבים והסנכרון.

קורא ה-ZIP נבדק מול `.otzplugin` **אמיתי** ב-`native/test/fixtures/`,
שנוצר בכותב ZIP חיצוני (‏`System.IO.Compression` של .NET) — כדי שהבדיקה
לא תהיה מעגלית.

## גרסאות ופרסום

הגרסה היא **מספר שלם אחד** (1, 2, 3…) ויושבת ב-`native/VERSION` בלבד. כל
דחיפה ל-`main` שכל הבדיקות בה עברו מקדמת את המספר, מתייגת `vN`, ומפרסמת
release עם ה-exe (`.github/workflows/ci.yml`).

התוכנה בודקת פעם אחת בהרצה אם יצא release חדש ומציגה על כך שורה. **אין
עדכון עצמי** — הסיפור מסתיים בכתובת שנפתחת בדפדפן.

### ה-CI של החבילה המלאה

`.github/workflows/bundle.yml` רץ יומית, וגם כשריצת CI הצליחה ב-`main`
(‏exe חדש), וגם ביד. בקצרה, מה שהוא עושה:

1. **זורע את עצמו מהחבילה הקודמת.** מוריד את החבילה שפורסמה, מחלץ ממנה
   את `Data\`, ומחלץ בנפרד את ה-exe שבתוכה (`unpack_overlay.mjs --slim`).
2. **מסנכרן** — ומכיוון שהמראה כבר על הדיסק, הוא מוריד מ-otzaria.org רק
   את הדלתא. עדכון של תוסף אחד עולה קובץ אחד ולא ‎96MB. אגב כך זה מריץ
   בדיוק את המסלול האינקרמנטלי שכונן של משתמש עובר בעדכון.
3. **מחליט אם לפרסם.** שתי השוואות, ודי באחת מהן:
   * המראה — `mirror_changed.mjs`, בהשוואת התוצאה עצמה.
   * ה-exe — בייט-לבייט מול זה שחולץ בשלב 1. בלי זה בינארי חדש לא היה
     מגיע לחבילה לעולם, כי המראה אינה משתנה כשהקוד משתנה.
4. **אורז ומאמת** — `pack_overlay.mjs`, ואז חילוץ חזרה והשוואה
   (`diff -r`) כדי שלא תפורסם חבילה שאינה נפרסת.

שני דברים ששווה לדעת:

**התג הוא `bundle` מתגלגל** — תמיד אותו אחד, מתעדכן במקום. הג'וב **אינו
מקדם גרסה ואינו מתייג `vN`**, משתי סיבות שבשתיהן מדובר בהתראת העדכון:
`isStoreReleaseTag` פוסל כל תג שאינו `^v?\d+$`, ולכן `bundle` נעלם
מבדיקת העדכון ואריזה אינה מודיעה למשתמשים על "גרסה חדשה" כשהקוד זהה;
ו-`fetchLatestStable` קורא דף אחד של 30 releases, כך שפרסום בכל ריצה
היה דוחף את כל ה-`v<N>` מחוץ לדף וההתראה הייתה מפסיקה לעבוד בשקט.

**המונים מנוטרלים מההשוואה** (`downloadCount`, הדירוגים). בלעדיהם
סנכרון שלא הוריד דבר עדיין הפיק קטלוג שונה — מונה הורדות אחד שזז — וכל
ריצה הייתה מפרסמת ‎96MB. קודי היציאה של `mirror_changed.mjs` זרים
לקוד שנוד מחזיר על חריג: `0` לפרסם, `3` אין שינוי, `2` תקלה — כדי
שקריסה של הכלי תפיל את הג'וב ולא תיראה כמו "אין מה לפרסם".

## הערות

* **תיקיית הנתונים תמיד צמודה לקובץ ההרצה ואינה ניתנת לשינוי** — זו
  הדרישה של עבודה מכונן נייד. כשאי אפשר לכתוב בה אבל יש בה קטלוג,
  התוכנה רצה במצב קריאה (ההתקנות כותבות למחשב) והיומן עובר
  ל-`%LOCALAPPDATA%`.
* **המאגר הפנימי של ה-WebView2 יושב ב-`%LOCALAPPDATA%` ולא ב-`Data\`** —
  הוא נגזר מהמחשב הזה, ואין טעם לגרור אותו על כונן נייד.
* **שם קובץ ההרצה אינו מכיל "אוצריא" בכוונה:** זיהוי ההתקנה של אוצריא
  עובד לפי השם, ו-exe בשם כזה שיושב ב-`C:\אוצריא` היה נבחר שם כהתקנה של
  אוצריא עצמה. הזיהוי מתאים גם ל-`otzaria` הלטיני, ולכן גם
  `Otzaria-Plugin-Store-Full.exe` נמצא ב-`OUR_OWN_EXE_NAMES`
  שב-`otzaria_probe.js`.
* **ההתקנה נמסרת לאוצריא** דרך `otzaria://plugin/install-local`, ולא
  בפרישת ה-ZIP בעצמנו — אוצריא מנהלת רישום פנימי לתוספים המותקנים,
  ופרישה ידנית עוקפת אותו. כשנתיב ההתקנה ידוע ה-URL נמסר לקובץ ההרצה
  עצמו ולא למערכת ההפעלה, כי התקנה **ניידת** אינה רושמת את הסכימה בכלל.
* **האייקונים** הם הווקטורים המדויקים של
  [Fluent UI System Icons](https://github.com/microsoft/fluentui-system-icons)
  (MIT). `extract_icons.mjs` מוציא מהגופנים רק את מה שבשימוש.
* ⚠️ **אין לערוך ביד את ערכות הצבעים** ב-`native/web/css/tokens.css` —
  הפלטה נבנית במרחב HCT, וגוון שנבחר "בעין" יוצא מהמשפחה.
